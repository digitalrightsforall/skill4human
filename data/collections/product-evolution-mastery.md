# 适用时机与语境 / Timing
> 产品不是功能的堆砌，而是进化的生物。本集锦适用于新产品定义、老产品转型、以及需要建立“产品增长飞轮”的时刻。

- **同一时机 (Co-occurrence)**: 在进行 `核心功能设计` 的同时，必须同步挂载 `用户反馈闭环`。没有反馈的产品只是开发者自嗨的孤岛。
- **时机接续 (Sequential)**: 先通过 `MVP` 验证核心逻辑，再利用 `网络效应` 驱动产品的生态级跃迁。

# 核心心法 / Philosophy
- **用户主权**: 产品的价值是由用户的使用场景定义的，而不是由说明书定义的。
- **持续减法**: 进化的本质是功能的收敛与认知的升维。
- **[认知增益]**: 获得“产品上帝视角”。让你能预见产品的未来演化路径，提前布下竞争护城河。

# 落地模型 / System
- **产品进化引擎 (Product Evolution Engine)**:
  1. **感知层**: 实时捕获用户的“非预期使用”信号，那往往是下一次进化的起点。
  2. **协议层**: 建立产品内部的模块化协作规则，确保系统可无缝扩张。
  3. **生态层**: 引导第三方开发者或用户参与价值共创。

# 执行动线 / Workflow
1. **启动“核心价值审计”协议** -> 2. **执行“逻辑滑梯”搭建** -> 3. **进行“反馈回路”校准** -> 4. **达成“产品生态化”跃迁**。

# 实战技巧 / Tactic
- **“刺破开发自嗨”**: 强制要求每一个新功能必须对应一个真实的、高频的用户痛点。
- **[启发式准则]**: 最好的产品是那个能让用户觉得自己变强大了的产品。
- **[认知增益]**: 提升“战略定力”。让你在海量需求面前保持冷静，不被噪音带偏核心方向。
- **[反面模式]**: 功能冗余陷阱。为了显得强大而不断增加无用功能，最终导致产品臃肿不堪。
