# 适用时机与语境 / Timing
> 完美的计划是执行的敌人。本集锦适用于资源极度受限、需求高度不确定、或需要进行“极限压力交付”的时刻。

- **同一时机 (Co-occurrence)**: 在进行 `功能排期` 的瞬间，必须同步挂载 `MVP (最小可行性) 审计`。严禁在第一阶段开发任何“非核心”功能。
- **时机接续 (Sequential)**: 先通过 `快速原型` 探测现实阻力，再利用 `精益迭代` 实现质量的闭环升级。

# 核心心法 / Philosophy
- **浪费即犯罪**: 所有不直接产生用户价值的工程动作都是需要被无情剔除的。
- **速度也是质量**: 在动荡的市场中，慢一步可能意味着整个逻辑的失效。
- **[认知增益]**: 获得“极限交付”掌控力。让你在资源匮乏的环境中，依然能产出具备“工业级标准”的成果。

# 落地模型 / System
- **精益执行引擎 (Lean Execution Engine)**:
  1. **脱水层**: 剔除所有装饰性需求，锁定“第一性功能”。
  2. **并发层**: 建立任务的异步执行协议，消除串行瓶颈。
  3. **校准层**: 通过日级的“站会”协议，实现逻辑的秒级对齐。

# 执行动线 / Workflow
1. **启动“核心假设”探测协议** -> 2. **执行“逻辑滑梯”构建** -> 3. **进行“全量自动化反馈”** -> 4. **达成“快速闭环交付”**。

# 实战技巧 / Tactic
- **“刺破开发幻觉”**: 强制要求每 24 小时必须有一个可运行的 Demo。
- **[启发式准则]**: 能够被交付的“残缺”作品，远好于永远处于“开发中”的完美蓝图。
- **[认知增益]**: 提升“现实控制力”。让你不再被进度条所绑架，而是成为节奏的操纵者。
- **[反面模式]**: 镀金效应。在核心功能尚未稳固时，过度关注 UI 细节或极端情况的处理。
