# 智慧逆向工程报告：1k Error Handling Wisdom (v4.7)

## 适用时机 / Timing & Context
- **典型情景**: 系统集成、处理不可靠的网络请求、或设计用户反馈界面时。
- **启动信号**: 当你写下第一个 `try` 块，或者在处理一个未捕获的异常（Unhandled Exception）时。
- **[启发式准则]**: 错误处理的水平决定了一个系统的“尊严”。

## 核心心法 / Philosophy
- **错误即契约**: 异常不是失败，而是函数在告知你它无法履行契约。
- **上下文是救命稻草**: 一个没有上下文（Context）的 Error 只是噪音。
- **[认知增益]**: 获得“心理韧性”，学会如何在高压和不确定环境下建立稳健的反馈系统。

## 落地模型 / System
- **异常分类学**: 
  1. **预期内异常 (Expected)**: 如网络超时。需要重试或优雅降级。
  2. **逻辑异常 (Logic)**: 如参数错误。需要立即修复代码。
  3. **不可抗力异常 (Fatal)**: 如内存耗尽。需要确保系统安全自毁并保留现场。
- **[反面模式]**: 吃掉错误。用一个空的 `catch` 块掩盖所有问题，这会让未来的调试变成噩梦。

## 执行动线 / Workflow
1. **捕获 (Capture)**: 在最接近错误发生的地方捕获它。 -> 2. **包装 (Wrap)**: 附加当时的上下文变量。 -> 3. **分发 (Dispatch)**: 根据错误类型决定是重试、报错还是静默记录。 -> 4. **呈现 (Show)**: 将技术术语转化为人类能懂的“指导性操作”。

## 实战技巧 / Tactic
- **错误码与文档**: 每一个报错都要带一个唯一的代码，以便用户在 Google 或 Wiki 中查询。
- **[启发式准则]**: 不要只告诉用户“出错了”，要告诉他们“现在该怎么办”。
- **[认知增益]**: 提升“同理心”，学会在他人处于挫败感（系统报错）时提供清晰的指引。
