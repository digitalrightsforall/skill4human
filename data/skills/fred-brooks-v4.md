# 智慧逆向工程报告：Fred Brooks Engineering Wisdom (v4.7)

## 适用时机 / Timing & Context
- **典型情景**: 管理大型软件项目、面临进度失控需要紧急加人、或在多团队协作中感到极其低效时。
- **启动信号**: 当你发现“增加人力反而减慢了进度”时，立即翻开此报告。
- **[启发式准则]**: 向进度落后的项目中增加人力，只会使项目更加落后（布鲁克斯法则）。

## 核心心法 / Philosophy
- **概念完整性 (Conceptual Integrity)**: 这是系统设计的核心。宁可牺牲部分功能，也要确保整个系统的逻辑风格是由一两个大脑主导的。
- **没有银弹**: 不要幻想某种新技术能解决由于系统内在复杂性带来的根本难题。
- **[认知增益]**: 获得“工程的敬畏感”，在大型项目的波涛中寻找那些能稳定船身的压舱石。

## 落地模型 / System
- **外科手术式团队**: 
  1. **首席程序员**: 负责所有的设计和核心代码，确保概念完整性。
  2. **副手**: 辅助、备份并进行挑战性审计。
  3. **专业工具人**: 负责环境、测试、文档等琐事，解放首席的大脑。
- **[反面模式]**: 民主式设计。让所有人轮流决定架构，结果会导致产出一个毫无灵魂的“四不像”。

## 执行动线 / Workflow
1. **确立首席大脑**: 明确谁是系统的灵魂，谁拥有最终裁决权。 -> 2. **建立显性约束**: 识别系统中的“本质复杂性”和“偶然复杂性”。 -> 3. **进行“沟通脱水”**: 建立标准的数据结构和接口，减少不必要的会议。 -> 4. **抛弃原型**: 接受第一个版本注定要被扔掉的事实，提前做好重写的准备。

## 实战技巧 / Tactic
- **吃自己的狗粮**: 设计者必须亲自使用并维护自己设计的系统。
- **[启发式准则]**: 优秀的程序员不仅仅是写代码，他们更是在构建一个可被理解的思想模型。
- **[认知增益]**: 提升“组织效率”，在极其复杂的人机系统中实现精准的推进。
