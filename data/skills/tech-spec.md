# 智慧逆向工程报告：High-Fidelity Tech Spec (v4.7)

## 适用时机 / Timing & Context
- **典型情景**: 启动中大型开发任务、重构核心链路、或引入新的中间件时。
- **启动信号**: 当你发现“需求已经清楚了，但不知道从哪儿下手”时。
- **[启发式准则]**: 写文档的时间是“投资”，写代码的时间是“支出”。

## 核心心法 / Philosophy
- **思想的预演**: 你的大脑是最高级的模拟器。在文档中写错是可以撤销的，在生产环境写错是需要回滚的。
- **具体到单行逻辑**: 拒绝模糊的“处理数据”，要具体到“遍历 A 数组，根据 ID 查找 B 映射，并计算总和”。
- **[认知增益]**: 获得“确定性”，彻底消除开发过程中的“盲目尝试”。

## 落地模型 / System
- **Tech Spec 标准结构**: 
  1. **Abstract (摘要)**: 3 句话讲清解决什么问题。
  2. **Technical Architecture (技术架构)**: 数据流图和类图。
  3. **Milestones (里程碑)**: 具体的交付时间点。
  4. **Risk & Mitigation (风险与规避)**: “如果 DB 挂了怎么办？”
- **[反面模式]**: 文档自嗨。写了几万字但没有一行能指导开发。

## 执行动线 / Workflow
1. **输入分析**: 彻底理清 PRD 中的业务逻辑。 -> 2. **草绘方案**: 快速在白纸上画出逻辑链路。 -> 3. **细节补全**: 填充数据结构、接口定义和关键伪代码。 -> 4. **评审修正**: 邀请同事进行“对抗性评审”，找出逻辑漏洞。

## 实战技巧 / Tactic
- **使用 Mermaid 画图**: 逻辑关系必须可视化。
- **[启发式准则]**: 如果一个 Tech Spec 写完后，你不能立刻开始写代码而不看任何外部文档，那这个 Spec 就是不完整的。
- **[认知增益]**: 提升“专业严谨度”，成为团队中那个“靠得住”的技术支柱。
