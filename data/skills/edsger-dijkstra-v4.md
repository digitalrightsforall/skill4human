# 智慧逆向工程报告：Dijkstra’s Intellectual Rigor (v4.7)

## 适用时机 / Timing & Context
- **典型情景**: 设计底层算法、优化核心逻辑、或发现系统存在深层次的、难以言说的混乱时。
- **启动信号**: 当你发现自己需要用 500 行代码来解释一个逻辑，且其中充斥着 `if-else` 的特殊处理时。
- **[启发式准则]**: 简洁不仅是美学，更是为了让大脑能够完全掌控程序的正确性。

## 核心心法 / Philosophy
- **抗击复杂性**: 复杂性是软件工程的死敌。任何增加复杂性的行为都是在犯罪。
- **关注点分离 (Separation of Concerns)**: 一次只处理一个问题，严禁逻辑耦合。
- **[认知增益]**: 获得“逻辑的纯净感”，通过极简的符号系统来实现极高难度的系统构建。

## 落地模型 / System
- **狄氏自律清单**: 
  1. **无 bug 设计**: 程序的正确性应当是通过推导得出的，而不是通过测试“凑”出来的。
  2. **拒绝“调试”**: 如果你需要频繁调试，说明你的逻辑从一开始就没想清楚。
  3. **优雅的归纳**: 寻找那个能覆盖所有特殊情况的通用数学表达。
- **[反面模式]**: 散漫的代码。使用模糊的命名、不规范的缩进和随意的全局状态。

## 执行动线 / Workflow
1. **定义前后验条件**: 在写任何代码前，明确：输入是什么？输出必须满足什么性质？ -> 2. **建立不变式 (Invariants)**: 找出在整个执行过程中永远保持不变的逻辑基石。 -> 3. **进行“纸上推演”**: 拒绝打开编辑器，先在白纸上写出完整的逻辑证明。 -> 4. **物理转化**: 将完美的逻辑翻译为代码。

## 实战技巧 / Tactic
- **禁绝 GOTO 思维**: 拒绝任何形式的非结构化跳转。
- **[启发式准则]**: 计算机是为了让人类表达思想而存在的，不是为了让笨拙的思想得以运行。
- **[认知增益]**: 提升“思维的颗粒度”，通过极致的自律获得极致的自由。
