# 智慧逆向工程报告：1k Defensive Coding (v4.7)

## 适用时机 / Timing & Context
- **典型情景**: 编写核心业务逻辑、处理外部 API 调用或处理用户敏感数据时。
- **启动信号**: 当你意识到“如果这里出错了，后果会很严重”时。
- **[启发式准则]**: 永远假设外部输入是带有恶意的，且底层依赖随时会崩溃。

## 核心心法 / Philosophy
- **防御性偏执 (Defensive Paranoia)**: 保护你的代码不受外部世界的混沌影响。
- **Fail Fast (快速失败)**: 错误应该在发生的第一时间被抛出，而不是在 10 分钟后的另一个逻辑块中导致诡异的崩溃。
- **[认知增益]**: 获得“系统级稳健性”，将 90% 的低级 Bug 阻击在上线前。

## 落地模型 / System
- **零信任边界 (Zero Trust Boundary)**: 
  - 所有跨边界的数据必须经过严格的 Schema 校验。
  - 所有的外部依赖（DB, API, File System）必须有超时和重试机制。
- **[反面模式]**: 盲目信任。假设网络永远通畅，数据库永远在线。

## 执行动线 / Workflow
1. **边界设防**: 在函数入口处检查前置条件（Pre-conditions）。 -> 2. **主路径收窄**: 确保逻辑流是单向且清晰的。 -> 3. **异常闭环**: 为每一个可能的错误定义明确的处理器。
2. **[启发式准则]**: 如果一个函数有 100 种失败的可能，你的代码应该准备好 100 种应对方案，哪怕只是记录日志。

## 实战技巧 / Tactic
- **Idempotency (幂等性)**: 确保同一操作执行多次的结果与执行一次相同。
- **[启发式准则]**: 宁可程序崩溃退出，也不要带着错误的状态继续运行。
- **[认知增益]**: 晚上能睡个安稳觉，不用担心半夜被报警电话叫醒。
