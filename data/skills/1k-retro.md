# 智慧逆向工程报告：1k Blameless Retrospective (v4.7)

## 适用时机 / Timing & Context
- **典型情景**: 项目结束、重大事故发生后、或者定期的团队同步会。
- **启动信号**: 当有人开始说“这都怪某某某”或者“如果当时不那样就好了”时。
- **[启发式准则]**: 复盘的目的不是为了寻找“谁错了”，而是为了寻找“系统哪里弱”。

## 核心心法 / Philosophy
- **无责备假设 (Blameless Assumption)**: 假设所有人在当时的情况下，都做出了他们认为最好的决策。如果结果是坏的，那是系统的错。
- **挖掘二阶原因**: 不要停留在“他忘了写文档”这种表象，要问“为什么系统允许他在不写文档的情况下上线？”
- **[认知增益]**: 建立“高心理安全感”的文化，让失败成为最廉价的学费。

## 落地模型 / System
- **复盘三部曲**: 
  1. **回顾事实 (What happened)**: 只谈客观时间线，不带主观情绪。
  2. **深度挖掘 (Why happened)**: 连问 5 个为什么，直达系统根源。
  3. **改进方案 (What next)**: 制定具体的、可衡量的、有责任人的动作。
- **[反面模式]**: 批斗大会。将复盘变成推卸责任和互相指责的战场。

## 执行动线 / Workflow
1. **时间线复原**: 所有人共同拼凑出事故的真实全貌。 -> 2. **关键决策点分析**: 找出那些“本可以走向不同结局”的转折点。 -> 3. **动作提纯**: 每一个问题必须对应一个“防御性动作”。 -> 4. **知识固化**: 将教训写入代码库的 `README` 或自动化脚本。

## 实战技巧 / Tactic
- **记录“差点出事”的事**: 那些没有酿成大锅、但确实存在隐患的小事，才是最有价值的预防素材。
- **[启发式准则]**: 最好的改进方案是“物理隔离”，其次是“自动化检测”，最差的是“加强培训”。
- **[认知增益]**: 获得“系统级免疫力”，不再在同一个坑里掉进去两次。
