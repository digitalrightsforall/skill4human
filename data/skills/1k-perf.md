# 智慧逆向工程报告：1k Performance Engineering (v4.7)

## 适用时机 / Timing & Context
- **典型情景**: 系统响应慢、资源占用率高、或面临大规模并发压力时。
- **启动信号**: 当用户开始抱怨“卡顿”，或者你的云服务账单出现异常飙升时。
- **[启发式准则]**: 性能优化的第一原则是：不要优化（Don't do it）。第二原则是：现在不要优化（Don't do it yet）。

## 核心心法 / Philosophy
- **瓶颈意识 (Bottleneck Consciousness)**: 系统中 80% 的延迟通常来自 20% 的代码。没找到瓶颈前的优化都是在浪费生命。
- **测量胜于直觉**: 程序员的直觉在性能领域极其不准。永远用数据说话。
- **[认知增益]**: 获得“系统级全局观”，学会将有限的精力投入到最高杠杆的优化点上。

## 落地模型 / System
- **性能三原色**: 
  1. **Latency (延迟)**: 一次操作要多久？
  2. **Throughput (吞吐量)**: 单位时间能处理多少请求？
  3. **Resource (资源占用)**: 内存和 CPU 烧了多少？
- **[反面模式]**: 散弹枪式优化。到处乱改代码，希望能撞大运提高一点性能。

## 执行动线 / Workflow
1. **建立 Baseline**: 在没有任何改动前记录当前的性能数据。 -> 2. **Profiling**: 使用工具找到真正的热点函数（Hotspots）。 -> 3. **假设验证**: 针对瓶颈提出改进假设并实施。 -> 4. **回归测试**: 验证改进是否有效，且没有引入新 Bug。

## 实战技巧 / Tactic
- **Caching (缓存)**: 最快的计算就是不计算。
- **[启发式准则]**: 如果优化的结果是代码可读性大幅下降，但性能只提升了 5%，请撤销它。
- **[认知增益]**: 提升“成本效益比”思维，无论在代码还是在人生中，都要学会识别核心变量。
