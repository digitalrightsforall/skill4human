# 智慧逆向工程报告：ADKAR Startup Change Model (v4.7)

## 适用时机 / Timing & Context
- **典型情景**: 初创公司引入新流程、技术栈切换、或组织架构大调整。
- **启动信号**: 当你发现“政策发了，但没人执行”或者“大家嘴上支持，心里抵触”时。
- **[启发式准则]**: 组织变革的失败，90% 不是因为技术方案不行，而是因为忽略了人的心理动线。

## 核心心法 / Philosophy
- **变革是原子级的 (Change is Individual)**: 组织不会变革，只有人会变革。如果不能影响到每一个具体的个体，宏大的转型战略只是幻觉。
- **先感性后理性**: 动力（Desire）永远优先于知识（Knowledge）。如果不解决“为什么要变”，再好的培训手册也是废纸。
- **[认知增益]**: 获得“推行意志”的能力，将混乱的抗拒转化为统一的合力。

## 落地模型 / System
- **ADKAR 五阶模型**:
  - **A (Awareness)**: 意识到变革的必要性（为什么是现在？）。
  - **D (Desire)**: 参与变革的愿望（对我有什么好处？）。
  - **K (Knowledge)**: 知道如何改变（具体的技能和工具）。
  - **A (Ability)**: 实现改变的能力（实战中的肌肉记忆）。
  - **R (Reinforcement)**: 巩固变革（防止回滚到旧习惯）。

## 执行动线 / Workflow
1. **诊断瓶颈**: 找出团队目前卡在 ADKAR 的哪一环（通常是 A 或 D）。
2. **场景模拟**: 针对 K 和 A 环节，不搞大课培训，搞真实业务场景的“结对编程”。
3. **建立反馈环**: R 环节需要即时的正向激励，哪怕是一个小的胜利也要公开表扬。
4. **[反面模式]**: 直接跳到 K（培训）。这是最常见的管理偷懒：以为发个文档大家就懂了。

## 实战技巧 / Tactic
- **1-on-1 攻心**: 针对核心反对者进行私人沟通，寻找其 D（愿望）的缺失点。
- **[启发式准则]**: 如果你不能用一句话说清楚“不改变会死在哪里”，那就不要启动 A。
- **[认知增益]**: 学会优雅地管理冲突，让变革成为团队的进化机会而非负担。
