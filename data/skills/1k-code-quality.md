# 智慧逆向工程报告：1k Code Quality System (v4.7)

## 适用时机 / Timing & Context
- **典型情景**: 当你在进行快速原型开发或长期项目维护，且感到“代码屎山”正在堆积时。
- **启动信号**: 每次提交代码前，或者当你觉得某段逻辑“虽然能跑，但看起来很别扭”时。
- **[启发式准则]**: 代码是写给人看的，只是偶尔由机器执行。如果你不能在 30 秒内向同事解释清楚这段逻辑，它就是低质量的。

## 核心心法 / Philosophy
- **代码即负债 (Code as Liability)**: 每一行你写下的代码都是未来的维护负担。优秀的工程师以“删代码”为荣，而非“增加代码”。
- **可预测性原则 (Predictability)**: 质量的本质是减少“意外”。遵循最小惊讶原则（Principle of Least Astonishment）。
- **[认知增益]**: 获得“长期掌控感”，避免陷入永无止境的 Bug 修复循环。

## 落地模型 / System
- **三层质量过滤 (Three-Layer Filter)**: 
  1. **意图层**: 变量命名是否反映了“为什么”而非“是什么”？
  2. **契约层**: 函数的边界（输入/输出）是否清晰且不可违背？
  3. **复杂度层**: 循环嵌套是否超过 3 层？函数长度是否超过一个屏幕？
- **[反面模式]**: 零成本假设。假设未来的开发者（包括 3 个月后的你）能瞬间记住当下的所有上下文。

## 执行动线 / Workflow
1. **意图自检**: 强制重命名那些模糊的变量。 -> 2. **逻辑剥离**: 将核心算法与外部副作用（I/O）彻底隔离。 -> 3. **边界强化**: 添加必要的防御性校验。
2. **[启发式准则]**: 如果你在写注释来解释“这段代码在做什么”，你应该重构代码让它自解释。

## 实战技巧 / Tactic
- **童子军规则**: 离开时代码库要比你进来时更干净一点。
- **[反面模式]**: 过度包装。为了所谓的“解耦”引入了 5 层接口，导致追踪一个简单的函数调用需要跨越 10 个文件。
- **[认知增益]**: 建立职业自尊心，让代码成为你的艺术品而非临时劳作。
